## What exists

### Plane 1: axon-feed (Phase 1, unchanged since 2026-10-20)
Order in `pipeline/run.py`: load store, collect, window, merge with store, resolve_redirects, enrich (extract), process (canonicalize, dedupe, tag, score), publish, save store. Modules: `collectors/` (arxiv, rss, github_releases, hf, hn, http with Throttle/Robots/Fetcher incl. `resolve`, registry incl. `host_limits`), `pipeline/` (window, canonicalize, redirects, extract, dedupe, tag, score, publish, store, run), `scripts/` (validate_config, validate_sources, capture_samples, export_schemas, inspect_feed, publish_data). Published layout (spec 5.4): `meta.json`, `latest.json`, `tags/<tag>.json`, `entities/<slug>.json`, `items/<id>.json`, `archive/`, `store.json`.
Run: `python -m pipeline.run --out ..\Axon\feed-out [--window-hours 72] [--no-store]` (production 168 via `collect.yml`). Inspect: `python -m scripts.inspect_feed <feed-out> [--top 15] [--untagged 25] [--tag <slug>] [--entity <name>] [--save PATH]`.
Real `collect.yml` (cron `7 */3 * * *`, `contents: write`, actions pinned to SHAs) and `scripts/publish_data.py` exist. `docs/go-live.md` is the first-push checklist for this repo.

### Plane 2: axon-template (Phase 2, 2026-10-22 to 2026-10-24)
Flow (`digest/pipeline.py`): `load_feed` -> extra_rss -> drop seen -> `rank` -> text for the top N -> summary cache -> router (primary, circuit breaker, fallback, extractive last resort) -> validated `Summary`. `digest/cli.py` renders, delivers, marks seen, writes `last_run.json` and, for Tier 3, `state/tasks/<id>.json`.
CLI: `python -m digest.cli run|init|onboard|feedback|notify-failure|validate-profile`. Local secrets: `.env` (git-ignored). No stubs remain: Phase 6 built `delivery/{telegram,slack,rss}.py`, `digest/onboarding.py` and the real `onboard.yml`.
Local run (PowerShell): `python -m digest.cli run --profile profile.yaml --feed <path-to>\Axon\Axon\feed-out --state-dir .local\state --outbox .local\outbox --dry-run` (add `--no-llm` for no key).

### Plane 3: axon-gateway (Phase 3, 2026-10-26)
Hono app, `createApp(deps)` (injected fetch, clock, sleep, rng, nonce). Layout: `src/index.ts` (routes, 405/404, no CORS), `a2a.ts` and `mcp.ts` (thin adapters over the core), `agentcard.ts`, `core/{updates,summarize,feed,deps}.ts` (the one contract), `providers.ts` (fixed provider URLs, key in a private field), `summarizer/{prompting,validation,llm,types}.ts` (port of the template), `prompts/summarizer.generated.ts` (generated from `prompts/summarizer_system.txt`), `budget.ts` (45-subrequest budget, concurrency pool), `ratelimit.ts`, `security.ts` (key-in-body detection), `env.ts` (config validation), `errors.ts`, `http.ts` (body cap, content type, JSON-RPC helpers). Stubs kept for Phase 4: `auth.ts`, `github/*`, `core/digest.ts`; `/register`, `/tokens` answer 501.
Behaviour in one paragraph: Tier 1 reads `tags/`, `entities/` shards (or `latest.json`) through `fetch` with Cloudflare edge caching (5 min), merges, filters, sorts and returns items without excerpts plus freshness metadata. Tier 2 resolves provider/key/model from headers, reads `items/<id>.json`, builds the 13.1 prompt exactly like the template, validates strictly, retries once, repairs key points, degrades per item to `not_summarized` with the snippet, fails fast on key or quota errors, runs 3 items at a time inside a 45-subrequest budget. A2A speaks protocol 0.3.0; MCP speaks revision 2026-07-28 (stateless, `server/discover`) and 2025-11-25 (`initialize` without sessions). Rate limits per IP: 60/min public, 10/min Tier 2 (Cloudflare binding, in-isolate fallback).
Scripts: `npm run prompt:generate|prompt:check|prompt:compare -- <template prompt path>`, `npm run bench`, `npm run dev`. Local run guide with PowerShell commands: `docs/local-run.md`.

## Environment constraints (company laptop)
- Outbound DNS is restricted: `Resolve-DnsName smtp.gmail.com` returns RCODE_REFUSED. SMTP cannot be tested locally. Do not work around IT policy (no DNS changes, tunnels or hotspots on the company laptop).
- Web traffic goes through a proxy; TLS may be inspected. Python/httpx: `SSL_CERT_FILE`; pip: `PIP_CERT`. DeepSeek calls from Python worked without extra settings.
- Node/npm and `wrangler`: expect proxy settings (`npm config set proxy` / `https-proxy`, `NODE_EXTRA_CA_CERTS`). `wrangler dev` runs locally without a Cloudflare login (confirmed in the sandbox); it prints a harmless `Request.cf ... workers.cloudflare.com` warning when Cloudflare is unreachable. `wrangler login`, `deploy` and `kv` need Cloudflare reachable and are deferred to the first push. If the proxy intercepts `localhost`, set `[System.Net.WebRequest]::DefaultWebProxy = $null` in the PowerShell session before `Invoke-RestMethod`.
- The Worker calls `api.deepseek.com` and `router.huggingface.co` from Cloudflare, not from the laptop, but `wrangler dev` runs the Worker on the laptop, so a Tier 2 smoke test needs those hosts reachable through the proxy (workerd does not read `HTTPS_PROXY`; if blocked, test Tier 2 only after deploy).
- Windows: read and write files with explicit UTF-8; `.gitattributes` in the gateway forces LF for the prompt files.

## Workflow conventions
Assistant ships new and changed files as a zip (`axon-<repo>-<phase>.zip`); the user unzips over the repo, runs `pip install -r requirements.txt -r requirements-dev.txt` (or `npm ci`) when dependencies changed, then the checks above, and pastes failures. A zip holds only new or changed files unless it says cumulative; apply zips in order. The Phase 3 gateway zip includes a regenerated `package-lock.json` (wrangler and a newer `workers-types` were added). The assistant states the expected test count and whether it was observed or derived, lists assumptions, and updates this file, the spec (Appendix C items numbered on from 62) and commit messages at the end of every phase.
Hard rules: no `# type: ignore` (Python) and no `any` / `@ts-ignore` (TypeScript), do not hand-edit generated or exported models (the gateway's `src/prompts/summarizer.generated.ts` is generated), run the formatter before the checks, keep secrets out of logs, files and chat.

**Working agreement from the Phase 5 chat (binding for Phase 6; also in `axon-PHASE6-BRIEF.md` section 1):** the user runs all suites on the Windows laptop; the assistant writes code and tests, compile-checks at most, and ships **stage zips** (`axon-<repo>-phase56-stageN.zip`, cumulative, only new and changed files) with exact PowerShell commands and expected counts (derived, not observed); after each stage the assistant reports what is built and what is pending and waits. Missing files are created, not reported as errors. Interim zips are packaged before risky work.
